### v4 的读数（`CFFFFFF6`）和它的**弱点**

| 位 | 读数 | 含义 |
|---|---|---|
| 1 | `C` | 冻结 |
| 2,3 | `F F` | CS 高时 MISO = `0xFF` |
| 4,5 | `F F` | CS 低时 MISO = `0xFF` |
| 6,7 | `F F` | 最近一个字节 = `0xFF` |
| 8 | `6` | 字节数÷4096 |

第 8 位那个 `6` 是**独立验证**：`spi_master` 每字节 16 个半周期 + 收尾半周期，
`clk_div`=123 → 2.5µs/半周期 → 42.6µs/字节；两个 2 秒阶段 = 4s ÷ 42.6µs
≈ 93,900 字节，对 65536 取模 = 28,364 = `0x6ECC`，高 4 位 = **6**。

> ⚠ **v4 的证据比我当时说的弱**：`miso_hi` / `miso_lo` 只锁了**阶段结束时的那一个
> 字节**，不是整个阶段。所以 v4 那次看到 `FF`，**不能排除"刚才大部分时间都是低的、
> 只是最后那一拍恰好是高"**。v6 把这一点补上：每个阶段数整个窗口里 0 比特的**总数**。

### v5 的读数（`CFF0000F`）

| 位 | 读数 | 含义 |
|---|---|---|
| 1 | `C` | 冻结 |
| 2,3 | `F F` | `zero_cnt` 饱和 —— 窗口里 0 比特 ≥255 个 |
| 4,5 | `0 0` | 第一个 ≠`FF` 的字节 = `0x00` |
| 6,7 | `0 0` | 第二个 = `0x00` |
| 8 | `F` | ≠`FF` 的字节数饱和（≥15） |

**CS 拉低发完 CMD0 之后，DAT0 被一路拉低。**

### v6 的读数（**已拿到，结论定了**）

| 情形 | 读数 | `zc_a` CS高 | `zc_b` CS低 | `zc_c` CS低+CMD0 | `zc_d` CS高 |
|---|---|---|---|---|---|
| **插卡** | `EFFFF000` | `00` | **`FF`** | **`FF`** | `00` |
| **拔卡** | `E0000000` | `00` | **`00`** | **`00`** | `00` |

**插卡时 DAT0 完全跟着 CS 走，跟命令一个字都没关系**（`zc_b` 是纯 CS 低、
MOSI 一路 `0xFF`、还没发过任何命令，就已经是低的）。这正是 v3/v4 里被判为
"已排除"的假设（b）—— **MISO 跟 CS 联动**，实测成立。

v4 那次读 `FF` 是假象：v4 每个阶段**只锁最后 1 个字节**，不是整段。

### ★ 结论：故障在卡这一侧，根因是**一张坏卡** ★

拔卡后四段全干净 —— B14 被内部上拉稳稳拉高，CS 拉低也不影响它。
所以：

* **板上的 DAT0 铜箔跟 CS 网络是分开的**（"板级短路"排除）
* 引脚映射（A14/A13/B14/A12）、上拉、FPGA 输入通路**全都是对的**
* 插卡就联动、拔卡就干净 → 是那张卡（或它跟卡座的接触）把 DAT0 和 DAT3 连在一起了

### ✅ 换卡后：**读到了 `E0007000`，通了**

| | `zc_a` CS高 | `zc_b` CS低 | `zc_c` CS低+CMD0 | `zc_d` CS高 |
|---|---|---|---|---|
| 坏卡 | `00` | `FF` | `FF` | `00` |
| 拔卡 | `00` | `00` | `00` | `00` |
| **好卡** | `00` | `00` | **`07`** | `00` |

```text
E 0 0 0 0 7 0 0
              └─ zc_a = 0   起始基线干净
        └─────── zc_c = 7   ← CMD0 的 R1 = 0x01（7 个 0）★
    └─────────── zc_b = 0   ← 好卡被选中且空闲时 DO 是高
```

**卡是活的，SPI 收发全通 —— 从 FPGA 引脚到卡座到卡，整条链路第一次跑通。**

> SD 初始化"从来没成功过"到此有了物理解释：**卡根本没能跟 FPGA 通话**。
> 跟 `spi_master`、时序、引脚映射、`fat32_reader.v` 都没关系 —— 那些是清白的
> （`fat32_reader.v` 本身仍未被验证，只是不再被怀疑）。

## 1. 本轮（v6）在测什么

还剩一个问题没答：**它是**一直**拉着（跟 CS 无关），还是**只在被选中时**拉着？**
这决定下一步查卡还是查板。

v6 把这两者分开：四个阶段，每个阶段数自己窗口里 0 比特的**总数**。

| 阶段 | CS | 发什么 | 结果 | 意义 |
|---|---|---|---|---|
| `PH_A` | 高 | 64 字节 `0xFF` | `zc_a` | 基线：不选中、没发过命令 |
| `PH_B` | **低** | 64 字节 `0xFF` | `zc_b` | ★ 严格复测 v4 的 PH_LO |
| `PH_C` | **低** | **CMD0** + 64 字节 | `zc_c` | 复现 v5 |
| `PH_D` | **高** | 64 字节 `0xFF` | `zc_d` | ★★ 取消选中，卡松不松手 |

`PH_C` 直接接在 `PH_B` 后面（CS 一直是低的），这正是真实驱动送命令的方式：
CS 拉低 → 灌 `0xFF` → 发命令 → 继续灌 `0xFF` 等响应。

**为什么 v5 那次不过滤 bit7**：v3 的 bit7 过滤器假设"响应和字节边界对齐"，
错位时一个 `0x01` 会变成 `0x80`（被过滤掉）或 `0x3F`（收下错值），读数失去唯一解释。
所以 v5/v6 都只数 0 的个数，不做任何过滤。

## 2. 上板怎么看（物理从左到右）

位选/段选都是低有效。上电后约 11 毫秒走完，然后永久冻结。

| 位 | 内容 |
|---|---|
| **第 1 位** | 阶段码：`9`=自检 `A` `b` `C` `d` = 四个阶段 **`E`=完成冻结** |
| 第 1 位的小数点 | 约 1Hz 闪 = 心跳。**不闪 = 先查时钟/复位，别查卡** |
| 第 2,3 位 | `zc_b` —— CS 低、没发命令（期望 `00`） |
| 第 4,5 位 | `zc_c` —— CS 低、发过 CMD0（v5 是 `FF`） |
| **第 6,7 位** | **`zc_d` —— CS 高、CMD0 之后 ★ 关键 ★** |
| 第 8 位 | `zc_a` —— CS 高、起始基线（饱和到 `F`，期望 `0`） |

数值含义：窗口 64 字节 = 512 位，计数器饱和到 `0xFF`。

* `00` = 这段时间 DAT0 一直是高（干净）
* `FF` = 至少 255 个 0（窗口一半以上是低）
* 其它 = 0 的实际个数（每字节 8 个）

停在 `E` 之后数值就冻结了，可以慢慢读。

## 4. 引脚对照（已核对原理图 + 已在位流 IO 报告中验证）

| 顶层端口 | FPGA 引脚 | 板上网名 | 卡座脚 | SPI 角色 |
|---|---|---|---|---|
| `sd_dclk` | **A14** | FPGA_SD_CLK | CLK | 时钟 |
| `sd_mosi` | **A13** | FPGA_SD_CMD | CMD | 主出从入 DI |
| `sd_miso` | **B14** | FPGA_SD_D0 | DAT0 | 主入从出 DO |
| `sd_ncs` | **A12** | FPGA_SD_D3 | DAT3 | 片选，低有效 |

（`fat32_probe.adc` 里注明 BANK0 经 R123 使能内部上拉）。

## 5. 自检阶段（前 3 秒）量什么

**先把表笔架好再上电** —— 窗口只有 3 秒。黑表笔接 GND，红表笔点**卡座**对应的脚：

| 量卡座哪个脚 | 应看到 | 对应 FPGA 引脚 |
|---|---|---|
| SD_CLK | 0↔3.3V 来回摆，约 0.67 秒一个周期 | A14 |
| SD_CMD | 0↔3.3V 来回摆，约 1.34 秒一个周期 | A13 |
| SD_DAT3 | 0↔3.3V 来回摆，约 2.69 秒一个周期 | A12 |
| **VDD** | **稳定 3.3V** ← 这条**从没确认过** | — |
| DAT0 | 稳定 3.3V（内部上拉；量到 0V 就是短地） | B14 |

**不插卡也要量**，量的是铜箔。⚠ 自检阶段是 `ph_cnt` 直接驱动脚，
**完全不经过 `spi_master`**，所以它证明不了 `spi_master` 在工作。

### 一个免费、马上能做的测量

**v5 位流烧完之后是冻结的**（第 1 位显示 `C`），那时 CS 是高、时钟停了。
用万用表量**卡座 DAT0 对地电压**：

* 读到 **3.3V** → 卡已经松手了，低电平只出现在命令窗口里
* 读到 **约 0V** → **现在就有东西在拉着 DAT0，而 CS 是高、时钟停着** ——
  这不是卡在 SPI 空闲时该有的行为，是硬故障

## 6. 厂商驱动为什么被绕开

`sd_card_top` 把初始化全包在内部，失败时外面只能看到 `sd_init_done` 一直是 0，
看不到卡在 CMD0、CMD8 还是 ACMD41。而且 `sd_card_cmd.v` 的 R1 等待超时是
`0xFFFF` 字节（100kHz 下 **5.24 秒**），超时后 `sd_card_sec_read_write`
**无限重试** —— 卡不响应时整个设计静默挂死，数码管上什么都不显示。

## 7. 每一版探针的来龙去脉（别重复走）

| 版本 | 干什么 | 结果 / 教训 |
|---|---|---|
| v2 | SD 初始化状态机 + **每 2 秒自动重试** | 读数 `st=0` 无法解释。**教训：读数一旦和时间相关，同一份结果就能对应好几种解释** |
| v3 | 去掉重试，终态**永久锁存** | 读出 `200FFFF9` → CMD0 的 R1 = `0x00`。但用了 bit7 过滤，会把错位响应吃掉或变形 |
| v4 | **纯物理测试**：不发命令，只做"CS 高读 2 秒 / CS 低读 2 秒" | `CFFFFFF6` → 通路没坏。但**每个阶段只锁了最后 1 个字节**，证据比当时说的弱 |
| v5 | 发真 CMD0，采**整个窗口**的原始字节，不过滤 bit7 | `CFF0000F` → **CMD0 之后 DAT0 被一路拉低** |
| **v6** | 四个阶段各数整个窗口的 0 比特总数：CS 高 / CS 低 / CS 低+CMD0 / CS 高 | 本轮 —— 分清"一直拉"还是"只在选中时拉" |

## 8. 前几轮踩过的坑

| 现象 | 真实原因 |
|---|---|
| 报「模块 wav_loader 不存在」 | `wav_loader.v` 里用 `buf` 当数组名 —— **`buf` 是 Verilog 关键字**。编译失败 → 模块未定义 → TD 标成 `AutoExcluded` |
| `CRITICAL-WARNING: already implicitly declared` | `top.v` 里 `bmp_*` 的 wire 声明放在了例化**之后** → 生成了 1 位隐式线网，32 位 LBA 会被截断 |
| 数码管全 0 / `0······0` | ① 位流是旧的（`bit` 早于源文件）② `seg7` 把 `0xF` 显示成空白 |
| 批量构建报 `gate.qor` 0 字节 / 退出码 255 | PowerShell 的 `Select-Object -First N` 拿到足够条目就**关管道并杀掉上游进程** |
| **构建"成功"但产物时间戳没变** | **命令行里的反斜杠被 Tcl 吃掉** —— `\r` 变回车，报 `couldn't read file`，**但退出码仍是 0**。TD 命令行一律用正斜杠 |
| v2 探针读数 `st=0` 无法解释 | 每 2 秒重试，所有读数都变成时间相关的。**改成终态锁存后同一读数只剩一种解释** |
| v3 探针读数 `0x00` 无法解释 | bit7 过滤器假设"响应和字节边界对齐"。**响应错位时该假设不成立** |
| v4 探针读数 `FF` 无法解释 | 每阶段只锁**最后 1 个字节**。**一拍的样本不能代表整个阶段** |
| v8 读数 `E00000FF`（所有命令零响应） | **`cs_n_ctrl` 漏了一个 `!`** —— `spi_master` 里是 `assign nCS = nCS_ctrl;`（低有效），所以 `cs_n_ctrl=1` 是"CS 拉高 = 卡没被选中"。注释写着"CS 低"，表达式却给出 1。结果前置阶段该 CS 高却低、命令阶段该 CS 低却高，**卡全程没被选中** |

**教训 1**：上板现象"和以前一样"时，先比 `bit` 和源文件时间戳，别急着改逻辑。
**教训 2**：退出码 0 **不代表**构建成功。查产物时间戳 + 日志关键词，发布前再 MD5 比一次。
**教训 3**：数码管上的每一个数都要能**唯一**对应一种原因；做不到就换一个量。
**教训 4**：一个样本不能代表一段时间。要在时间上说话，就得数整段。
**教训 5**：**极性/低有效信号写反，五个静态检查器一个都抓不到**（不是语法错、不是多驱动、不是端口不匹配）。
凡是 `nCS`/`rst_n`/`低有效` 这类信号，写完表达式回头对一遍注释里的文字 ——
注释说"低"、表达式就得给出 0。上板读数"什么都没发生"时，这是第一个要查的。
